Detectors and validator

Both detectors are plain functions in src/metrics.js. The model never computes them; it reads them through get_day_metrics.

1. Task drift: detectDrift(events, now, minMinutes = DRIFT_MINUTES || 15)

  1. An anchor_start event sets the anchor: the assigned task plus its evidence (assigned_by).
  2. An event with a trigger (ai_remark, mention, self) in another context starts a side-quest.
  3. It ends at the first event back in the anchor context, at now, or (never spanning days or a new anchor) at the last side-quest event.
  4. Kept only if minutes ≥ threshold. Output: {anchor, anchor_evidence, side_quest, trigger, trigger_event, start, end, minutes}.

2. Rubber-stamp review: reviewFlags(events)

A closed, "reviewed" item counts as closed with proper review only if no flag fires:

RuleFires when
too_fastapproval review_seconds < 60 × lines / 100 (1 min per 100 lines; our heuristic)
no_cino ci_run event in the item
unverified_claima non-CI event says "tests pass/passed" and there is no CI run
no_review_activity0 review comments and 0 files viewed

Live repos (github-live.js): approval moment = earliest of first review (COMMENTED counts; GitHub blocks self-approval), an "LGTM" comment, or the merge. Every merge is the closure. A bare "LGTM" is not review activity.
